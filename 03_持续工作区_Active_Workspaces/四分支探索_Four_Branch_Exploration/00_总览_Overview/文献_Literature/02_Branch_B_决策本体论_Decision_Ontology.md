# Branch B：DeFi 决策本体论——透明系统中的信用信息生产

**核心直觉**：DeFi 的"透明性"是一个陷阱。所有交易可见（交易透明）不等于有关偿付能力的信息可见（信用透明）。这个区分类似于：银行能看到你的银行卡账单（交易透明），但银行不知道你下个月会不会失业（不透明事件）。在 DeFi 中，借贷协议看到的是 on-chain actions，但它们看到的究竟是**关于偿付能力的信号**，还是仅仅是一个**被公开记录的行为档案**？如果是后者，那么"DeFi 是透明的"这句话在信用判断的意义上就是空洞的——它混同了"看得到"和"看得懂"。

---

## 1. 与 V4 的连续与断裂

### 连续性
- 继承 V4 的终极问题：纯链上行为能否用于信用判断？
- 继承观察者相对性（observer relativity）：什么信息对谁是可见的？
- 继承 V4 的所有数据基础设施（Dune 查询、HF 自计算、主动/被动区分）

### 断裂
- **理论锚点从行为经济学（Prospect Theory）彻底转向信息经济学（Information Economics）+ 本体论（Ontology）**
- V4 问："DeFi 借款人的行为偏差包含信用信号吗？"
- Branch B 问："在 DeFi 中，'信用信号'本身是什么？它的生产条件是什么？透明性在什么条件下能产生真正的信用信息，在什么条件下只是制造 Noise？"
- **这不是"扩展"V4，而是为 V4 的经验发现（如果 BDM 确实预测清算）提供一个更高层级的解释框架**——"为什么"行为偏差包含信用信号

## 2. 理论框架（两层结构）

### 第一层：信息经济学——信用信息的本质

#### 2.1 信息不对称的标准理论（Baseline）

Stiglitz & Weiss (1981) 的经典框架：信贷配给之所以存在，是因为银行无法区分"好"和"坏"的借款人（逆向选择），也无法完全监控借款人事后行为（道德风险）。结果是：利率上升 → 安全借款人退出 → 留在池中的平均风险上升 → 银行不提高利率而直接配给信贷。

这一框架的关键前提是：**存在某种信息，它对于银行是不可观察的，但对于借款人是已知的**。银行通过抵押、合约条款等机制来部分解决这个问题。

DeFi 的承诺是：因为它透明且无需信任，这些信息不对称问题已被消解。**但这是否成立？**

#### 2.2 DeFi 中的信息生产悖论

在 DeFi 中：
- ✅ 所有**交易**是公开可见的（全透明度）
- ❌ 但**偿付意愿**和**偿付能力**不能从交易中直接读取

这就创造了一个有趣的翻转：
- 在传统金融中，银行**不透明**（银行不知道你下个月是不是会失业）是一个缺陷
- 在 DeFi 中，协议**完全透明**（协议知道你的每个交易），但依然不知道你的偿付能力——**全透明 = 全噪声**

这是一个根本性的洞察：**透明度是信息生产的条件，但也是信息过载的条件**。在 100% 可观测的环境中，"信号"和"噪声"是同一样东西——取决于你用什么分析框架去组织它。

#### 2.3 信息生产函数

因此，B 的理论贡献不是"DeFi 存在不对称信息"（这 trivial），而是提出**信息生产函数（Information Production Function, IPF）**的概念：

$$\mathcal{I}(x_t, \mathcal{F}_t) = \text{Signal}_{credit}(x_t | \mathcal{F}_t)$$

其中：
- $x_t$ 是时间 $t$ 的链上行为（交易序列）
- $\mathcal{F}_t$ 是信息治理框架（分析框架——本体、理论、模型）
- $\mathcal{I}$ 是从原始行为中生产信用信息的过程
- 输出是"该行为对信用判断意味着什么"的信号

**核心论题**：$x_t$（行为）本身不包含信息——只有当一个本体论框架 $\mathcal{F}_t$ 被使用时，$x_t$ 才成为信用信号。如果你不知道你要找什么，你看不到任何东西。

> 这与"怎么都行"的哲学（Feyerabend）不同，更接近信息论中的"信号必须在接收端被解码"的编码理论。

### 第二层：决策本体论——为信用判断构造一个显式的知识结构

#### 2.4 从"分析框架"到"本体"

如果信用信息的生产依赖于分析框架，那么什么框架更可能产生好的信号？

**知识本体（Ontology）的工程传统**（Gruber, 1995; Gómez-Pérez et al., 2004）提供了一套严格的概念化工具：
- 定义领域中的**类**（Class）：借款人类型、行为类型、风险类型
- 定义**关系**（Relation）：什么行为"证据"了什么能力/意愿
- 定义**公理**（Axiom）：逻辑规则——已知某行为，可以推断什么属性
- 定义**实例**（Instance）：具体地址的具体行为

**关键创新**：在 DeFi 中，交易的本体结构是**自动可提取的**。这是因为所有的交易都是形式化的（Ethereum 交易 = 一个标准化的数据结构）。在传统金融中，行为是高度非结构化的（柜台对话、邮件沟通、电话协商）——在 DeFi 中不是。

这意味着**DeFi 是唯一一个可以为信用判断构建显式的、机器可读的本体的金融场景**。这不是工程选择，是根本的结构属性。

#### 2.5 Palantir 式推理的类比

Palantir 的核心洞察是：调查分析的瓶颈不是缺少数据，而是缺少**语义整合**——把不同来源、不同格式、不同粒度的数据映射到同一个概念框架中，让分析者可以问"这个人与这个人什么关系"而非"给我看这个表"。

在 DeFi 信用判断中，同样的问题存在：
- 你能看到地址 A 在协议 X 上借了钱，地址 C 在协议 Y 上做了抵押
- 但这些事实必须被**语义连接**：地址 A 和地址 C 是同一个 label 吗？借的资产是不是来源于 Aave 的闪电贷？这个借款是用于杠杆还是真实消费？
- 这些连接需要的不是"更多数据"，而是一个**显式的本体结构**来决定哪些关系在信用判断中是相关的

Branch B 不是要构建 Palantir（工程上的)，而是要**以本体的思维方式重新概念化 DeFi 中的信用信息生产问题**。

## 3. 操作化方案

### 3.1 研究设计：两阶段的混合方法设计

**阶段一：本体构建（定性/计算性）**
1. **实体与关系的提取**
   - 从 Aave V2 的全部交互中，提取所有可观测的实体类型：EOA 地址、合约地址、Token 地址、协议地址
   - 提取所有可观测的关系：转账、授权、借款、还款、清算、闪电贷
   - 判断哪些关系在信用判断中是潜在相关的——不是所有关系都是信用信号

2. **本体定义（Conceptual Level）**
   - 定义信用判断的基本概念：偿付意愿（willingness to repay）≠ 偿付能力（ability to repay）
   - 为每个概念定义可观测的"证据"：什么可观测行为用作"偿付能力"的证据？
   - 示例：
     - 频繁的小额还款 → 证据：行为上的偿付意愿
     - 在 HF=1.0 时加抵押 → 证据：对清算的认知，隐含的偿付意愿
     - 从不显式地被清算（从不留下坏账） → 证据：历史偿付能力
     - 持有 Cryptopunk / ENS → 证据：长期投资倾向，隐含低风险

3. **本体编码（Formal Level）**
   - 将概念关系写成形式逻辑或一阶谓词

**阶段二：本体验证——"信息性"的信度检验**
1. 将"本体"转化为可计算的信用预测特征
2. 检验这些本体衍生特征在预测清算风险时的增量信度：与 BDM、HF 动态、账户属性等传统特征做赛马
3. 检验"本体的新信息"的独立性质

### 3.2 关键研究问题

- **RQ1（本体存在性）**：在 DeFi 信用判断中，哪些本体类型（偿付意愿、偿付能力）有显式的链上对应证据？哪些没有？
- **RQ2（信息生产）**：使用本体提取的特征是否超越了传统特征的信用预测力？
- **RQ3（可泛化性）**：定义在 Aave 上的本体是否可以转移到 Compound 而信息性不显著损失？

### 3.3 方法工具箱

- **形式概念分析（FCA）**：Ganter & Wille (1999) 的 FCA 天然适合从对象-属性表中推导概念层次
- **描述逻辑（Description Logic）**：用于写本体的形式语言
- **图神经网络（GNN）** 作为近似实现：如果本体定义为图结构，GNN 自然可以学习图上的消息传递

## 4. 失败判据

| 场景 | 判据 | 降级方案 |
|------|------|----------|
| 本体特征不超越传统特征 | 赛马中 F1/AUC 不优于 M_hf | 报告 DeFi 的信用信息与行为偏差等价——无需额外的本体 |

## 7. 核心优势与风险

### 为什么 B 最原创
- DeFi 的"透明度"被反复讨论，但从**信息生产**的角度没有人做工作
- 把"本体"从工程工具升级为**分析概念**是一个跨学科动作（将 CS 本体与金融信息生产连接）
- 可能是唯一一个不需要对大量数据进行复杂建模的方向（概念贡献就是主要贡献）

### 为什么 B 最高风险
- 你需要说服三个不同的学科：信息系统（IS）学者、金融经济学审稿人、CS 本体工程师
- "本体"这个词在 CS 和社会科学中有完全不同的含义——需要大量 definitional work
- 实证验证部分可能不足以支撑整个论文——如果本体特征与传统特征在预测力上等价，概念贡献是否成立？
- 委员会可能不理解为什么一个金融 PhD 要做"本体"

### 适用场景
- 适合**高理论化的 PhD 论文**或**概念论文作为第一条主线**
- 不适合作为硕士论文或投 CV/ML 导向的会议
- 如果被拒绝，B 可以退化为纯概念文章（风险更低，但影响力也更低）

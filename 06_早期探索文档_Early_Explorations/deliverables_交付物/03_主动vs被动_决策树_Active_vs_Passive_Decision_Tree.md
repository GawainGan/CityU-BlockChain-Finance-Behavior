# V4 主动 vs 被动清算分类决策树

**版本**：V4-1
**日期**：2026-06-19
**目的**：为 RQ1 的前景理论检验建立"主动补救 vs 被动清算"的无歧义分类规则，解决盲点自检中的"生死所在"

---

## 一、分类体系总览

```
观察到的链上交易（tx）
├── 1. 交易发起者判定
│   ├── tx.from == borrower_address → 用户发起（进入路径 A）
│   └── tx.from != borrower_address → 非用户发起（进入路径 B）
│
├── 路径 A：用户发起的交易
│   ├── 2a. 事件类型判定
│   │   ├── Supply (deposit) → A1: 主动加抵押
│   │   ├── Withdraw → A2: 主动减抵押
│   │   ├── Borrow → A3: 主动增借
│   │   ├── Repay (repayer == borrower) → A4: 主动还款
│   │   └── Collateral enable/disable → A5: 抵押品操作
│   │
│   └── 3a. HF 上下文判定（基于自计算的 HF 值）
│       ├── current_HF > 1.5 → 安全区域操作（前景理论：收益域）
│       ├── 1.0 < current_HF ≤ 1.5 → 逼近清算操作（前景理论：损失域边界）
│       └── current_HF ≤ 1.0（技术上不应存在，除非链上状态延迟）→ 异常，需人工审查
│
└── 路径 B：非用户发起的交易
    ├── 2b. 事件类型判定
    │   ├── LiquidationCall → B1: 被动清算
    │   └── Repay (repayer != borrower) → B2: 第三方代还（极罕见，通常伴随清算）
    │
    └── 3b. 清算发起者分类
        ├── liquidator ∈ 已知 MEV 机器人集合 → B1a: MEV 清算
        ├── liquidator 通过闪电贷操作 → B1b: 闪电贷清算
        └── liquidator 为普通地址 → B1c: 手动清算
```

## 二、前景理论检验的操作化映射

### 2.1 损失厌恶检验

**预测**：HF 下降（逼近清算）时的补救幅度 > HF 上升（远离清算）时的增险幅度

| 行为分类 | HF 变化方向 | 操作类型 | 预期方向 | 测度 |
|---------|-----------|---------|---------|------|
| 损失域反应 | HF↓ (1.5→1.1) | A1 加抵押 / A4 还款 | 补救幅度大 | $\Delta\text{USD}_{\text{remediation}}$ |
| 收益域反应 | HF↑ (1.1→1.5) | A3 增借 / A2 减抵押 | 增险幅度小 | $\Delta\text{USD}_{\text{risk-taking}}$ |
| **损失厌恶系数** | — | — | $\lambda = \frac{\Delta\text{USD}_{\text{remediation}}}{\Delta\text{USD}_{\text{risk-taking}}}$ | $\lambda > 1$ 则支持 H1a |

**关键控制**：配对 $|\Delta\text{HF}|$ 相同，仅方向不同

### 2.2 参考点效应检验

**预测**：HF=1 处行为发生不连续跳变

| HF 区间 | 操作分类 | 观测量 |
|--------|---------|-------|
| (0.8, 1.0) | 已被清算（B1）或极限补救（A1/A4） | 补救概率/幅度的断点 |
| (1.0, 1.2) | 逼近清算——"危险区" | 补救概率是否在 HF=1 处有跳跃 |
| (1.2, 1.5) | 中等安全 | 正常操作频率 |
| (1.5, ∞) | 安全区域 | 低频操作 |

**RDD 设计**：以 HF=1 为断点，左极限 = 清算后被动状态，右极限 = 清算前主动状态

**问题**：HF=1 左侧（已被清算）的操作都不是"主动"的，所以传统 RDD 在此处的识别策略需要调整。

**解决方案**：改用**接近度设计**——比较 HF 在 (1.0, 1.1) vs (1.1, 1.2) vs (1.2, 1.5) 的行为差异，测试是否存在 HF 越接近 1.0，补救行动概率/幅度的**加速增长**（非线性凸增）

### 2.3 递减敏感性检验

**预测**：远离 HF=1 后，对同等 $|\Delta\text{HF}|$ 的反应递减

| HF 距离 | 等距 HF 变化 | 预期反应 |
|---------|------------|---------|
| 近参考点：HF 1.0→1.1 | +0.1 | 强反应 |
| 中距离：HF 1.5→1.6 | +0.1 | 中等反应 |
| 远参考点：HF 2.5→2.6 | +0.1 | 弱反应 |

**检验**：补救行动幅度对 $|HF - 1|$ 的二阶导数是否为负

## 三、分类决策树（逐笔交易）

对每笔涉及借款人的交易，按以下流程分类：

```
输入：一笔链上交易 tx，涉及借款人地址 B

Step 1: 判定交易发起者
  ├── tx.from == B → 标记为"用户发起"，进入 Step 2
  └── tx.from != B → 标记为"非用户发起"，进入 Step 5

Step 2: 判定事件类型（用户发起）
  ├── 事件 = Supply/Deposit → 分类 = A1（主动加抵押）
  ├── 事件 = Withdraw → 分类 = A2（主动减抵押）
  ├── 事件 = Borrow → 分类 = A3（主动增借）
  ├── 事件 = Repay AND repayer == B → 分类 = A4（主动还款）
  ├── 事件 = Collateral Enable → 分类 = A5a（启用抵押品）
  └── 事件 = Collateral Disable → 分类 = A5b（禁用抵押品）

Step 3: 计算 HF 上下文
  ├── 计算 tx 执行前一区块的 HF_pre
  ├── 计算 tx 执行后一区块的 HF_post
  └── ΔHF = HF_post - HF_pre

Step 4: 判定 HF 区间
  ├── HF_pre ∈ (1.0, 1.1] → danger_zone = "critical"
  ├── HF_pre ∈ (1.1, 1.3] → danger_zone = "warning"
  ├── HF_pre ∈ (1.3, 1.5] → danger_zone = "moderate"
  ├── HF_pre ∈ (1.5, 2.0] → danger_zone = "safe"
  └── HF_pre > 2.0 → danger_zone = "very_safe"

Step 5: 判定事件类型（非用户发起）
  ├── 事件 = LiquidationCall → 分类 = B1（被动清算）
  │   ├── liquidator ∈ flash_loan_contracts → B1b（闪电贷清算）
  │   ├── liquidator ∈ mev_bot_set → B1a（MEV 清算）
  │   └── else → B1c（手动清算）
  └── 事件 = Repay AND repayer != B → 分类 = B2（第三方代还）

Step 6: 时间上下文判定
  ├── 距离最近一次 B1 事件 < 24h 且分类 ∈ {A1, A4} → 重新标记为 C1（清算后修复）
  ├── 距离最近一次 B1 事件 < 24h 且分类 ∈ {A3, A2} → 重新标记为 C2（清算后增险）
  └── 无近期 B1 事件 → 保持原分类

输出：
  - 分类代码（A1/A2/A3/A4/A5a/A5b/B1a/B1b/B1c/B2/C1/C2）
  - HF_pre, HF_post, ΔHF
  - danger_zone
  - 距最近清算的时间
```

## 四、关键假设与风险

### 4.1 假设 1：tx.from 可靠地标识交易发起者

**风险**：
- 合约钱包（如 Gnosis Safe / Multisig）的 `tx.from` 是合约地址而非最终用户
- 代理交易（如通过 MetaSwap 的路由交易）`tx.from` 可能是路由合约

**应对**：
- 识别已知合约钱包地址集合，单独分析或排除
- 在 PoC 中统计合约钱包发起交易的比例

### 4.2 假设 2：HF 可在交易前精确计算

**风险**：
- Dune 不提供实时 HF 快照，需自计算
- HF 依赖价格预言机（Chainlink），价格更新有延迟
- 区块级 HF 计算需要该区块的精确价格数据

**应对**：
- 使用 Dune 的 `prices.usd` 表获取小时级价格
- 对同一小时内的多笔交易使用同一价格（接受精度折衷）
- 在结果中报告价格粒度对 HF 计算的影响

### 4.3 假设 3：清算事件完整覆盖

**风险**：
- Dune 的 `lending.borrow` 可能遗漏部分清算事件（解码错误、合约升级等）
- Aave V2 → V3 迁移期间可能有数据缺失

**应对**：
- 使用 Aave 官方 subgraph 交叉验证
- 与 Gadzinski & Liuzzi (2025) 的 25,798 笔清算事件总数对比，检查覆盖度

### 4.4 假设 4：闪电贷清算不压倒性地主导

**风险**：
- 如果闪电贷清算占 90%+，则 HF 从 1.0→0.99 的窗口只有几秒，借款人无时间进行"主动补救"
- 此时"逼近清算阈值时的行为"样本量可能不足

**应对**：
- PoC 必须量化闪电贷清算占比
- 如果占比较高，将分析聚焦于**清算前 7 天的行为**（而非清算前几分钟），因为前景理论的预测不限于最后一刻

## 五、BDM 构念的具体构建

基于以上分类，BDM（Behavioral Deviation Measure）由以下 DeFi 特有维度构成：

| BDM 维度 | 操作化 | 前景理论对应 | 传统金融是否有对应物 |
|---------|--------|------------|-------------------|
| **补救超配度** | 实际加抵押/还款金额 / 理性模型推荐金额 | 损失厌恶（$\lambda$） | 有——止损超额 |
| **参考点跳变度** | HF 穿越 1.1/1.0 时操作频率的变化幅度 | 参考点效应 | 有——止损线行为 |
| **抵押品切换方向** | 逼近清算时是否切换到波动资产 | 递减敏感性+风险偏好翻转 | **无——DeFi 独有** |
| **清算后恢复模式** | 被清算后是修复还是逃跑 | 损失域持续冒险 | 有——revenge trading |
| **闪电贷窗口非行动** | 清算前 HF<1.5 期间无任何操作的天数占比 | 风险感知钝化 | 部分——inattention |

**关键**：维度 3（抵押品切换方向）是 DeFi 独有的，传统金融没有"在 margin call 前把国债抵押换成科技股抵押"的对应物。这是 BDM 构念新颖性的核心来源，直接回应盲点自检"检查 3：构念改名"的批判。
